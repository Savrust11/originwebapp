# 条件・限界の隣接表示：通信なしの独立試作

このディレクトリは通常アプリ・相談APIから取り込まない。既存ゲート、
資料採用・公開承認、DB、実利用者情報は変更しない。
外部モデルへ送信するコード・ボタンを持たない。

## 二つの表示を混同しない

- **架空画面例**：原文に照合して編集した短い研究説明。保存済みモデル
  回答の修正版でも、新たなモデル出力でもない。採用・公開前の参考表示。
- **保存済み回答の検証**：Q05〜Q11の生回答・当時の判定をそのまま表示。
  不合格は検証用にのみ表示し、条件を付加しても完成回答としない。

## 安全上の境界

確認済みカタログの原文・版・該当箇所・ハッシュ・引用範囲を検証し、
事前に対応付けた条件だけを本文の隣に表示する。質問や回答の自由記述から
対象条件を抽出・推定しない。モデルが原文IDを付けたという理由だけで、
その主張の意味が正しいとは扱わない。

本文と条件の意味照合は、本文と条件データのハッシュに結び付いた独立記録。
未支持の主張・矛盾があれば本文は不合格。未知の文言の矛盾を網羅的に
自動判定する機能ではなく、本文が変われば照合記録は無効となる。

確認済みカタログと編集例は別の明示的照合記録に固定される。表示ファイルを
再生成しても新しい文言を自動承認しない。条件・短文・出典のいずれかが変わる
場合、別の原文照合を行わずに照合ハッシュだけを更新してはいけない。

対象条件が未確認・不適合なら個別助言は返さない。この試作では一致でも、
既存ゲートと採用・公開承認がないため個別助言を開放しない。
医学的適用の確認や承認の代わりに画面表示テストを使わない。

## 新しい評価案と過去の採点

`evaluation-proposal.json` は一般向けの**今後の案**であり未採用。
必須の条件と意味は常に保持し、数値の詳細は質問が求めるかを評価前に固定。
理解・判断に影響しない背景だけを任意とする。
過去の数値要件・rubric・モデル判定を変更しない。

## 保持と検証

`history-integrity.mjs` は既存の評価・原文・ゲートのハッシュを確認する。
最初のスナップショットは排他的に新規作成し、上書きできない。
派生表示・今回の検証記録はすべて
`evidence-work/condition-display-offline/` に出力する。
モデル通信は追加0、既存累計13/20、17,093 microUSD、予算1,000,000 microUSD。

通信を遮断した検証コマンド:

```sh
env -i PATH="$PATH" LANG=C.UTF-8 LC_ALL=C.UTF-8 TZ=UTC \
  node --import ./prototypes/evidence-consultation/condition-display/offline-lockdown.mjs \
  --test tests/evidence-condition-catalog.test.mjs \
  tests/evidence-condition-display-policy.test.mjs tests/evidence-condition-integration.test.mjs
```

検証はローカルの派生表示JSONを再生成するが、過去記録は書き換えない。
画面検証は `verify-browser.mjs` で自己完結HTMLを file:// で開き、
HTTP(S)通信を遮断して行う。
