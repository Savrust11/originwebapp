# 一時PostgreSQLによるテスト

## 対象と禁止事項

通常の開発DB・本番DBには接続しない。既存のデータ・接続情報のコピーや、
通常アプリの起動、Secrets変更、公開は、この手順に含まない。
テスト実行ごとに新しく作成した一時DBとアプリだけを操作する。

## 実行入口

既存の環境変数を引き継がないシェルから実行する。
`PATH` はプログラムの検索用で、DB接続情報ではない。

```sh
env -i PATH="$PATH" LANG=C LC_ALL=C TZ=UTC \
  node --import tsx tests/run-ephemeral-tests.mjs lifecycle
```

これが成功してから、新しい一時DBで全対象を実行する。

```sh
env -i PATH="$PATH" LANG=C LC_ALL=C TZ=UTC \
  node --import tsx tests/run-ephemeral-tests.mjs all
```

対象を絞る場合は `authz`、`supporter`、`provisioning`、
`development`、`browser` を指定する。各実行でも先に接続なしの安全確認と
アプリの起動・終了確認を行う。

`TEST_DATABASE_URL`、`TEST_DATABASE_APPROVED_SHA256` は手動登録しない。
以前の手順書にある外部DBの事前登録方式ではなく、今回所有確認した
一時DBだけの接続情報を、プロセス内で生成する方式に変更した。
通常のDB設定・外部アプリURLを渡した場合は停止する。
個別のDBテストを直接実行して保護を回避しない。

## 分離の仕組み

- PostgreSQLの既存バイナリを使用し、毎回新しい非公開の一時フォルダに初期化する。
- 認証情報は毎回生成。パスワードは非公開ファイル経由で渡し、接続文字列や引数に入れない。
- TCPはループバックのみ。Unixソケットも専用フォルダ内に限定する。
- 最初のSQL接続より前に、起動したPIDと開始時刻、保存先、PIDファイル、
  TCP/Unixソケットの実際の所有プロセスをLinuxの管理情報で照合する。
- 接続先がローカルであることや、応答することだけでは許可しない。
- 子プロセスの環境は必要な項目から組み立て、通常のDB認証情報やSecretsを継承しない。
- アプリの待受開始は起動した子自身からの通知で確認する。

これは同じ実行ユーザーでコードを書き換えられる攻撃者に対する完全な隔離装置ではない。
通常のテスト操作で既存の保存先に接続しないための仕組みである。

## 表と架空データ

`tests/safety/ephemeral-schema.mts` が現在の `shared/schema.ts` から
空DB用のSQLを生成し、サポーターの追加構造を補う。
アプリのDBモジュールや通常のDrizzle接続設定は読み込まない。
SQLの適用は所有確認済みの一時DBだけで行う。
データは既存テストと開発用の架空データ作成処理で用意する。

## 終了と失敗時

テストとアプリ、PostgreSQLの順に、所有を記録したプロセスだけを停止する。
テストが起動する追加サーバーも終了待ちの対象とする。
停止に失敗したものがあっても、他の所有プロセスの停止は試みる。
停止を確認してから、今回の一時フォルダを削除する。
ブラウザの結果・スクリーンショットも削除対象の専用フォルダ内に保存する。

起動後に所有を記録できなかった場合や停止を確認できない場合は、
無理に削除せず残存場所を報告して失敗扱いにする。
中断時には後続テストを開始しない。SIGKILLや環境全体の停止などでは
後片付けを保証できないため、残存物を自動再利用しない。
名前の一致だけによる広範囲の削除・プロセス停止は行わない。

テストの出力には秘密情報が混じる可能性があるため、生の出力は転送しない。
成功・失敗と、事前に定めた起動失敗の分類のみを表示する。

## 通常ゲート回答経路の専用確認

通常アプリを起動せず、所有するループバック上の既存非公開試作HTTPハンドラ、
`checkOfflineAnswer` と実検索経路だけを
20件の架空質問で確認する専用グループは次のとおり。

```sh
env -i PATH="$PATH" LANG=C LC_ALL=C TZ=UTC \
  node --import tsx tests/run-ephemeral-tests.mjs normal-route-verification
```

このグループは一般の `lifecycle` を使わない。所有確認済み一時PostgreSQL、
空スキーマ、接続情報を持たない管理コンテキストの生成・終了を専用
`normal-route-lifecycle` で確認してから、本体を実行する。通常アプリ、
`server/index.ts`、外部AI、外部HTTPは起動・呼出ししない。専用テスト子が
待受する既存試作HTTPは `127.0.0.1` の所有確認対象だけに限定する。E01〜E04は
原文のままdraft/unapprovedとして取り込み、公開や人による承認を模擬しない。
結果は `evidence-work/model-evaluation/normal-route-results.{json,md}` に残り、
一時保存先を停止・削除できた後にだけ `destroyed` と確定する。
