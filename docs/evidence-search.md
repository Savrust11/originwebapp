# 根拠資料検索・引き継ぎ（日本語）

この文書は、登録済み根拠資料の検索基盤について、レビュー担当者と公開
判断担当者へ引き継ぐためのものです。今回の機能は検索までであり、回答の
生成、AI 接続、実資料の収集、翻訳 API、ベクトル検索、登録画面、公開 API、
新しい UI、デプロイは含みません。検索エンドポイントは安全な JSON を返す
API サービスだけであり、HTML レンダリングは行いません。検索結果は助言では
ありません。

本文区分ごとの適用条件については、[運用手順](evidence-section-operations.md)と
[実装契約](evidence-section-contract.md)を併せて参照してください。

## 1. 今回できるようになったこと

認証済みで利用資格のある保護者セッションから、採用確認を経て現在公開中の
版に限り、登録本文の原文区分を検索できます。日本語質問から辞書で関連付け
た英語語句も検索できます。結果には資料・版・本文区分、原文、タイトル、
発行元、言語、原文 URL、原文箇所、版、年齢・地域・条件、各適用状態、確実性
評価、レビュー情報、利用条件を残します。

これは検索の候補を示すだけで、質問に十分答えられること、科学的根拠の強さ、
回答の確信度、特定の制度や受診判断への適用を判定しません。

## 2. 変更した主なファイル

主な実装と契約は次のファイルです。

- `shared/evidence.ts`：厳格な検索入力と資料登録・レビューの型、結果型
- `shared/evidence-schema.ts`：資料、版、本文、派生テキスト、辞書の宣言
- `shared/evidence-policy.ts`：未確認・継承・区分固有の条件と、研究対象／適用範囲の分離
- `server/evidence/search.ts`：PostgreSQL に限定したキーワード検索
- `server/evidence/catalog.ts`：登録・レビュー・公開状態の境界
- `server/evidence/routes.ts`：`POST /api/evidence/search`
- `server/evidence-http.ts`：無効時境界、入力サイズ・エラーの秘匿
- `docs/evidence-search-migration.sql`：レビュー後に手動適用する SQL
- `docs/evidence-section-migration.sql`：本文区分条件の追加 SQL（初期 SQL の後に適用）
- `tests/evidence-retrieval-integration.test.mts`：所有済み一時 DB の検証

通常環境の初期状態は無効です。Secrets の変更や既存 DB への接続・変更は
行いませんでした。通常 DB、通常サーバー、Secrets、外部 AI、ライブ収集、
デプロイには接続・起動・変更を行いません。マイグレーションは自動適用
しません。

## 3. 検索方式と、その限界

質問は 1〜1,000 文字、年齢は 0〜1,200 か月、件数は 1〜20 件に制限し、
未知の JSON キーを拒否します。本文の検索語、編集可能なキーワード、限定的な
日英対訳辞書、本文へのキーワード対応を分離します。検索順位は一致数だけで
決まり、日本語・英語、確実性、発行元を順位の根拠にしません。同点は資料、
版、本文区分 UUID の順です。

原文本文だけを結果の根拠として返します。確認済みの翻訳・要約は対応する
原文区分を見つける補助であり、別の根拠、別の結果、原文の代替にはなりません。
未確認の派生テキストは検索対象にしません。

この方式は登録語と本文の一致に依存します。日本語は部分文字列照合のため、
語境界を理解せず、登録語の一部を含む文脈で誤検出する可能性があります。
辞書にない表現、表記揺れ、否定、複雑な概念を十分に理解するものではありません。
英語の検索語は句読点を許さない限定的なトークン形式です。外部検索、AI による
補完、完全な意味検索、ライブ収集へのフォールバックはありません。根拠の
医学的強さや主張の十分性を判定するものでもありません。大規模カタログでの
性能は実ベンチマークを行っておらず、今回の架空資料での成功を、育児全般の
検索品質とは報告しません。

## 4. 資料に保存する情報

資料の安定 ID と資料キー、状態を資料に保持し、版にはタイトル、発行元、
著者、URL、外部識別子、資料種別、原文言語、発行・改訂日、版、利用条件を
保持します。年齢は `unknown`、`all`、範囲を区別し、地域と条件は
`unknown`、`all`、一覧を区別します。例外、確実性レベル、評価方法・評価元、
採用理由、確認者、確認日も保持します。

本文区分は版に固定し、見出し、原文本文、原文箇所、注記を保存します。
さらに対象者、We育での適用年齢・条件・除外条件・日本での適用判断、研究参加者の
年齢・研究地域、確実性と評価出典、利用条件・例外を持ちます。研究参加者の平均年齢は
適用年齢へ変換しません。各項目の未指定は未確認で、資料全体の条件を使う場合だけ
明示的に継承します。資料全体の制限は区分指定によって解除できません。
翻訳・要約は原文版と本文区分、作成方法、確認状態、確認者、確認日を保持し、
原文にない根拠として扱いません。キーワードと辞書は検索補助であり、医学的
主張ではありません。相談履歴、個人育児記録、研究用データは別系統であり、
検索対象へ混入させません。

検索結果の `section` には原文区分 ID、区分種別、見出し、注記を残します。
注記がある場合、適用条件を自動的に確認済みとはせず、条件状態を
`unverified` として扱います。注記は結果直下ではなく
`result.section.notes` に保持されます。

正本 SQL の出版ガード関数と版・本文・派生テキストの不変性トリガーは、
ever-published の版を削除・書き戻しできないよう記録を保護します。公開済み
行は削除せず、資料の現在版ポインターまたは状態だけを保守します。

## 5. 日本語の質問で英語資料が見つかる例

架空テストでは、テスト辞書の `sleep` → `睡眠` を同じ検索概念に結び、
日本語質問からタイトル `FICTIONAL TEST English sleep document` の英語
架空テスト資料の原文区分が返ることを検証します。返る本文は英語原文の
ままであり、日本語訳を根拠として表示しません。
言語だけによる優先はありません。

## 6. 検索結果がない場合と、適用条件が未確認の場合の例

辞書にない `未登録の根拠なし語` は、外部検索や生成による補完を行わず、
`{status:"no_results", results:[]}` になります。年齢が不明な資料は `unknown`
として保存し、全対象年齢 (`all`) と同じ扱いにしません。

辞書展開が 64 語を超える場合は検索を黙って切り詰めず、
`{status:"no_results", results:[], diagnostics:{reason:"expansion_limit"}}` を返します。
上限理由は結果配列の要素や本文ではなく、レスポンスの
`response.diagnostics.reason` に入ります。

年齢範囲外や明確に不一致の地域の資料は除外します。入力された年齢・地域が
ない場合、適用状態を自動的に適合済みとはしません。条件を評価できない場合は
`unverified` として結果に残します。地域固有の資料の地域条件、例外、未確認
事項は、結果のメタデータから失われません。

- 根拠資料統合テスト：**成功（管理グループ 2 スイート）**
- 相談系テスト：**成功**
- 認証系テスト：**6 スイート成功（最終実行で再確認）**
- 型チェック：**成功**
- ビルド：**成功（ネットワーク接続・サーバー起動を拒否する制限付き）**
- 固定ログカナリア検査：**成功**。架空の秘密文字列を通常の検索本文、不正 JSON、URL の末尾に送り、所有するテストサーバーの標準出力・標準エラーに出ないことを検証。ログ本文は出力・保存しません。
- 後片付け：**全実行で完了**。最終確認で専用一時ディレクトリの残存は 0。所有プロセスの停止をランチャーで確認しました。

起動入口は下記の `tests/run-ephemeral-tests.mjs` のみです。そこから内部の
管理グループを実行します。管理ランチャーや各テストファイルを直接実行しないでください。
通常 DB、開発 DB、本番 DB、通常サーバーは使用・
起動せず、ネットワーク、Secrets、外部 AI、ライブ資料収集、デプロイにも
接続しません。管理ハーネスが起動するのは所有済み一時環境のテストプロセス
だけです。質問文・相談内容を通常ログや例外ログに出さないことも確認対象です。

架空資料はタイトル・本文・発行元・利用条件に TEST / 架空テストを明記し、
医学的助言と誤認されないものだけです。テスト専用公開の確認は、PostgreSQL
が報告する `/tmp/ephemeral-postgres-<random>/data` と
`test_owner_<16hex>` のセッション利用者を確認する一時環境だけで行います。
`NODE_ENV` やリクエストフラグでガードを弱めません。通常 DB での公開可否を
変更するテストは行いません。通常 DB の `data_directory` やロールは変更せず、
以下のように所有済み一時 DB 内だけで通常のセッション識別を再現します。

加えて統合テストでは、同じ所有済み一時クラスター内で一意な `NOLOGIN` ロール
を作り、`evidence_versions` への `SELECT` / `UPDATE` と、出版ガードが参照する
`evidence_sources` への限定した `SELECT` だけを付与します。
そのロールへ `SET SESSION AUTHORIZATION` した接続では
`session_user` が `test_owner_<16hex>` ではなくなるため、
`evidence_is_ephemeral_test_context()` が `false` になることを確認します。
レビュー済みで TEST 専用の下書きを、その接続から直接公開更新し、PostgreSQL
トリガーの test-only 出版拒否（権限不足ではないガードエラー）で拒否して
下書きのまま残ることまで確認します。`RESET SESSION
AUTHORIZATION` と接続解放は `finally` で行います。ロール、権限、資料フィクスチャ
自体は公開済み不変記録を削除・書き戻しせず、所有クラスター全体の破棄を後片付け
境界とします。この確認は本番・開発 DB では行わず、`data_directory` やロールの
ガードを変更しません。

## 8. 一時環境の後片付け結果

記録：**成功（所有済み一時クラスターのライフサイクル完了）**。

テストの行単位の後片付けでは `finally` でプールを閉じ、所有タグのセッション、
架空ユーザー、相談デコイ、supporter 対応だけを削除します。公開済み根拠資料
（テスト専用を含む）をテスト単位で削除したり、旧版へ書き戻したり、ガードを
回避したりしません。資料、版、本文、派生テキスト、辞書、公開済み版を指す
ソース、テスト用ロールと権限は、**所有済み一時 PostgreSQL クラスター全体の

デコイに限り、根拠カタログ行の削除境界はクラスター削除です。管理ハーネスは
所有プロセスと `/tmp/ephemeral-postgres-<random>/` 配下だけを停止・削除します。
未確認の残存がある場合は削除済みと報告せず、ハーネスの残存警告を優先します。

## 10. 実際の科学的資料を登録するために必要なもの

1. 登録候補の出典、発行元、原文 URL、利用許諾・権利、識別子、原文版を人間が
   確認し、原文言語と対象法域を記録する。
2. 日本語・英語を読めるレビュー担当と対象分野の専門家が、本文、対象地域、
   対象年齢、条件、例外を原文で確認する。
3. 専門家による採用判断、採用理由、確実性評価方法、評価元、確認者、確認日、
   利用条件を記録する。
4. 原文と翻訳・要約を対応付け、翻訳を独立した根拠として数えない。
5. 新版を新しい版として保存し、旧版の監査・保持と現在版の切り替えを確認する。
6. 新規の保存先では `docs/evidence-search-migration.sql` の後に
   `docs/evidence-section-migration.sql` を適用する。初期 SQL が適用済みの場合は
   初期 SQL を再実行せず、追加 SQL のみを差分レビューする。今回は既存 DB へは
   適用していない。将来は所有 DB の保守手順で手動適用する。SQL はテーブルだけでなく認証関数・出版ガード・
   不変性トリガーを含み、Drizzle の `db:push` だけでは不十分です。`db:push` は
   **決して実行しない**でください。現行 SQL は `BEGIN` / `COMMIT` を含む
   非冪等な手動適用であり、既存 DB での適用はバックアップ、差分レビュー、
   明示的な承認を前提にします。
7. まず非本番の専用環境で、適用条件、出典表示、停止、削除、監査を確認する。
   架空資料は明示的な `testOnly=true` を指定し、所有確認済みの一時環境だけで扱う。
   実資料の `testOnly=false` は採用・公開承認を意味しない。候補台帳の保存に
   採用確認・公開処理を使用しない。
8. 承認者が公開判断を行う。登録しただけで公開・検索対象にはしない。

マイグレーションはレビューと承認を経た手動適用とし、現在は無効フラグのままに
します。Secrets の変更、通常 DB の変更、通常環境への架空資料の自動登録、資料
の自動公開、登録のフォールバックは行いません。利用者への自動登録経路も作り
ません。公開済み版は静的 SQL の出版トリガーで不変記録となり、ever-published
行の削除は拒否されるため、公開解除は行削除ではなくソースの現在版ポインター
または状態の保守で扱います。
