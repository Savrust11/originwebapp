# 非公開AI相談試作：実装範囲と安全上の境界

## 今回できること／できないこと

現在の4資料・11区分だけを扱う、未接続の回答準備試作です。
通常アプリには登録していません。実モデルへの送信・回答生成はありません。
画面に出る確認質問や停止案内は固定ルールによるシステムの案内であり、
実際のAI回答でも、モデル品質の見本でもありません。

専用ボタンは、その時点の確認済み入力をサーバーへ渡し、改めて資料を検索します。
ブラウザから送られた本文、出典、過去の検索結果、履歴、家族情報は根拠として
受け入れません。取得した本人別の本文と必須文脈から回答用の境界を作ります。

実装は `prototypes/evidence-consultation/answer-*.mts` と
`AnswerPanel.tsx`。専用の一時サーバーだけに `/api/prototype/answer` が
あります。既存の相談保存機能や通常の認証／起動処理には接続していません。

## 回答の扱い

- 対象者ごとに分ける。子どもの年齢を保護者へ、兄弟の健康条件を別の子へ流用しない。
- 適用条件未確認：確認事項を示し、適合済みとして提案しない。
  資料側の採用・日本への適用等は運営の審査事項であり、
  相談者の自己判断で「確認済み」に書き換えるものではない。
- 対象外・根拠なし・検索語未対応・検索未完了：知識で補わず、理由を示す。
- 将来の生成候補は「相談への説明」「根拠がある場合の提案」
  「分からない点」の単位で、資料・版・区分の参照を持つ。
- 研究結果とガイドの推奨を混同しない。分類が不明な根拠を勝手に
  公的推奨や研究とみなさない。研究の対象外へ効果を保証しない。
- 診断、投薬指示、個別治療は対象外。簡単な語句検出だけで全ての
  言い換えを防げるとは扱わず、実モデル評価と安全な表示承認は別途必要。

## 外部AIへ送る予定の項目

今回は一切送信しない。将来の送信境界は以下に限定する。

| 項目 | 内容・制限 |
|---|---|
| 固定ルール | 根拠限定、未確認の保持、禁止行為、出力形式。相談文・資料と分離する |
| その対象者について確認した相談内容 | 自由文に含まれる氏名等は事前の確認・除去が必要。自動匿名化できるとは保証しない |
| 確認済み条件 | 子ども／保護者の区分、必要な歳・月齢、必要な健康条件の「ある／ない／不明」 |
| 本文と必須文脈 | サーバーで取得した現在版の原文。方法・対象条件・例外・限界を省略しない |
| 根拠の識別と条件 | 資料ID・版ID・区分ID、研究／ガイド種別、条件・不確実性 |

送らない項目：育児記録、個人記録、相談履歴全体、家族コード、アカウントID、
セッション、子どもの内部ID、リクエストID、連絡先、資料審査担当者の個人情報、
ブラウザの保存領域、不要な出典URL等。根拠資料のIDは出典対応に必要な識別子で、
利用者の識別子とは別に扱う。

回答候補用の境界は1対象者ずつとし、外部には匿名の対象トークンを使う。
複数対象者を含む相談文をそのまま各対象者へ送るのは避ける。
対象者別の送信文確認と、余計な識別情報を含まないことの確認が未整備なら、
外部接続を有効にしない。

相談サービス利用の説明・同意と、研究利用への同意は別。
今回は研究同意の収集、研究向け保存、利用履歴の保存を追加していない。

## 出典、現在版、命令混入

回答候補は未信頼データとして扱い、本人の検索結果に含まれる
資料ID・版ID・区分IDの組合せだけを認める。知らないID、別版、
今回取得していない区分、別対象者の区分、捏造URLは表示へ進めない。
本文を引用するときは対応する必須文脈も含める。

将来の候補処理では、生成後にもサーバーで再検索して内容・条件の
スナップショットを比較する。変化があれば以前の根拠による回答を採用しない。
ただしこれは原子的な公開／更新制御の代わりではない。
`evidence-publication-concurrency-open-issue.md` の競合は引き続き未解決。

固定ルールと、命令を含み得る相談文・本文は別の領域へ分ける。
資料や相談文からモデル設定、道具、URL取得、実行する処理を変更させない。
モデルの一般知識・外部検索・別モデルへの自動切替は使わない。
それでも、プロンプトの区切りや語句検査だけで命令混入への耐性を
証明できるわけではない。実モデルによる攻撃テストは未実施。

**正しい出典IDでも、説明が本文に支持されるとは限らない。**
英語の条件・例外・不確実性が日本語で保持されること、資料間の違いを
正しく説明できること、診断等を暗に勧めないことは、人の評価が必要。
構造検査の合格を回答品質や医学的採用の合格として扱わない。

## 緊急性が疑われる場合

緊急の心配が「ある／分からない」のとき、または限定的な危険表現を
検出したときは、通常回答を停止する。検索前に止め、モデルは使わない。
静的な停止案内のみで、モデルに連絡先を作らせない。

**未解決**：判断基準の専門家による確認、地域別の案内先と受付条件、
案内先の維持管理、見逃し／過剰停止の評価。現在の語句検出は完全ではなく、
「該当しない」と判定しても安全を保証しない。この試作は救急の判断には使えない。

## 通信・二重送信

UIで同時実行を抑止し、入力変更・キャンセルで古い結果を捨てる。
サーバーでも同一リクエストIDの二重実行を拒否する。
完了済み結果をそのまま再表示すると古い版の根拠になり得るため、
同じIDの再利用は拒否し、新規操作で再検索する。

プロセス内の有限・期限付き管理であり、再起動や期限を越える永続的な
重複防止ではない。将来の有料実接続では別途設計が必要。
将来用の通信境界では、完了した応答だけを検査する。途中の文章は表示せず、
途中終了・タイムアウト・キャンセル・通信失敗を成功に変換しない。

## 検証と未検証

専用入口：`npm run test:evidence-prototype`。
新規の所有確認済み一時DBと専用loopbackサーバーだけを使う。
通常アプリ用ライフサイクルも使わない。直接テストファイルを起動しない。

代替応答はテストファイル内だけで、状態・形式・参照拒否・通信境界を検査する。
実モデルによる日本語の質、根拠への忠実性、医学的安全性、
命令混入耐性、実課金、遅延は未検証。

外部接続の候補、必要な許可・設定、参考費用は
`evidence-ai-connection-options.md` を参照。
