## STEP 1: データベース + API（まずこれを貼る）

```
招待コード（Invitation Code）機能を実装してください。

## 概要
- LINEログイン成功後、初回のみ招待コードの入力を求める
- 正しいコードが入力されたらアプリのホーム画面に進む
- 2回目以降のログインではコード入力をスキップする

## データベース（PostgreSQL）

invitation_codes テーブルを作成：
- id: SERIAL PRIMARY KEY
- code: VARCHAR(20) UNIQUE NOT NULL（例: "BUDOU-A3K9"）
- is_used: BOOLEAN DEFAULT FALSE
- used_by: VARCHAR(255)（LINEのユーザーID）
- used_at: TIMESTAMP
- created_at: TIMESTAMP DEFAULT NOW()

usersテーブルに以下のカラムを追加（なければ）：
- invitation_verified: BOOLEAN DEFAULT FALSE

## Express API

### POST /api/auth/verify-code
リクエスト: { "code": "BUDOU-A3K9" }
処理:
1. ログイン中のユーザーのセッションからLINEユーザーIDを取得
2. invitation_codes テーブルでcodeを検索
3. コードが存在しない → 400エラー「無効な招待コードです」
4. コードが既に使用済み（is_used = true） → 400エラー「この招待コードは既に使用されています」
5. コードが有効 →
   - invitation_codes の is_used = true, used_by = ユーザーID, used_at = NOW() に更新
   - users の invitation_verified = true に更新
   - 200 OK「招待コードが確認されました」

### GET /api/auth/me
既存のユーザー情報取得APIに invitation_verified フィールドを含めるようにする。
フロントエンドはこの値を見て、コード入力画面を出すかホーム画面を出すか判断する。

## 招待コードの生成
管理用のシードスクリプトまたはAPIを作成：
- POST /api/admin/generate-codes
- リクエスト: { "count": 50, "prefix": "BUDOU" }
- 処理: 「BUDOU-XXXX」形式のコードを指定数生成してDBに挿入
  （XXXXはランダムな英数字4文字、大文字のみ）
- レスポンス: 生成されたコードの一覧をJSON配列で返す

セキュリティ: この管理APIは簡易的なパスワード保護でOK（ヘッダーに x-admin-key を含める）。
環境変数 ADMIN_KEY にキーを設定する。
```

## STEP 2: フロントエンド（STEP 1が完了したら貼る）

```
招待コード入力画面をReactで実装してください。

## 画面遷移フロー
1. ユーザーがアプリを開く
2. 未ログイン → LINEログイン画面を表示
3. ログイン済み & invitation_verified = false → 招待コード入力画面を表示
4. ログイン済み & invitation_verified = true → ホーム画面を表示

## 招待コード入力画面（InvitationCodePage）のデザイン
- アプリのブランドカラー（紫 #7B2D8E）を使用
- 画面中央に以下を配置：
  - We育のロゴまたはアイコン
  - 「招待コードを入力してください」というタイトル
  - テキスト入力フィールド（プレースホルダー: "例: BUDOU-A3K9"）
  - 入力は自動的に大文字に変換する
  - 「確認」ボタン（紫色）
  - エラーメッセージの表示エリア（赤色テキスト）
  - 「招待コードをお持ちでない方は、We育のLINE公式アカウントにお問い合わせください」というテキスト

## 処理
- 「確認」ボタン押下 → POST /api/auth/verify-code にコードを送信
- 成功 → ホーム画面にリダイレクト
- 失敗 → エラーメッセージを表示（「無効な招待コードです」等）
- 送信中はボタンをローディング状態にする

## ルーティング
- /invite → 招待コード入力画面
- 既存のルーティングに、invitation_verifiedチェックのガードを追加
- invitation_verified = false のユーザーは全ページで /invite にリダイレクト
```

/admin （簡易パスワード認証: 環境変数 ADMIN_KEY の値を入力してアクセス）

## 表示する情報

### サマリー（画面上部）
- 登録ユーザー数 / 50名（プログレスバー付き）

### ユーザー一覧（テーブル）

- アカウント登録日時
- 使用した招待コード
- 最終ログイン日時

ソート: 登録日の新しい順

### 招待コード一覧（テーブル）
| コード | ステータス | 使用者 | 使用日 |
表示項目:
- 招待コード
- 未使用 / 使用済み（バッジで色分け）
- 使用したユーザーのLINE名（未使用なら空欄）
- 使用日時

### コード生成ボタン
- 「新しいコードを生成」ボタン
- クリック → 生成数を入力するモーダル → POST /api/admin/generate-codes
- 生成後、コード一覧にCSVダウンロードボタンを表示

## デザイン
- シンプルで見やすいデザイン
- アプリのブランドカラー（紫 #7B2D8E）
- レスポンシブ対応（スマホからも確認できるように）

## 環境変数の設定（Replitの Secrets に追加）

Replitの左メニュー「Secrets」（鍵アイコン）を開いて、以下を追加してください：

| Key | Value | 説明 |
|-----|-------|------|
| `ADMIN_KEY` | `（自分で決めた長い文字列）` | 管理画面のパスワード |

※ LINE関連の環境変数（CHANNEL_ID, CHANNEL_SECRET）は既に設定済みの前提です。

---

## 実装後の確認手順

1. **コード生成のテスト**
   - ブラウザで `/admin` にアクセス
   - ADMIN_KEY を入力してログイン
   - 「新しいコードを生成」で50件生成
   - コード一覧が表示されることを確認

2. **招待コードフローのテスト**
   - シークレットウィンドウでアプリを開く
   - LINEでログイン
   - 招待コード入力画面が表示されることを確認
   - 間違ったコードを入力 → エラーが出ることを確認
   - 正しいコードを入力 → ホーム画面に進むことを確認
   - 一度使ったコードを別のアカウントで使う → エラーが出ることを確認

3. **2回目のログインテスト**
   - アプリを閉じて再度開く
   - コード入力なしでホーム画面が表示されることを確認
